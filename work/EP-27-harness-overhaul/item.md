# EP-27 基盤の抜本改修（verify の回復・文書の仕組み・拡張点の整備）

## 背景（オーナー方針 2026-07-10）
全体レビューの結果、目的（複製した案件で AI エージェントが迷わず部品に辿り着き・品質を黙って落とせず・
完了を自己申告できない）に対して、次の欠落が確認された。

1. **`uv run verify` が Windows で失敗する**。`subprocess` の `text=True` に `encoding=` が無く、
   ロケール（cp932）で UTF-8 の日本語出力を復号できない。緑でない状態では「緑を保ったまま各部を
   差し替える」という進め方そのものが成立しない。→ T-0164 で解消。
2. **ドキュメントを最新に保つ仕組みが「形式」しか守っていない**。参照の実在は検査するが、記述と実装の
   食い違い・規範の重複・撤去済みの仕組みへの参照は止まらない。→ T-0165・T-0167・T-0168 で一部解消。
3. **メタルールの改訂・撤回の経路が無い**。追加の流れしか設計されておらず、撤回漏れが実在する。
4. **拡張点の欠落**。分割器・昇格の判定・区間・統計モデリングが差し替え可能になっていない。
   → 昇格の判定は T-0171（`harness/gates.py`）で解消。分割器・区間・統計は未着手。
5. **champion を正規手段で戻せない**。`change_threshold` は旧版の再昇格を必ず阻む（判定として正しい）。
   切り戻しは昇格ではないので、判定を通さない別経路が要る。→ T-0175。

## 何をするか
- verify を緑に戻す（T-0164）。以降のすべての前提。
- 文書の仕組み（doclint の拡張・撤回済み識別子の検査・doc_sync による生成）。
- メタルールの改訂（ルールは手段であるという条文と、その歯止め）。
- 既存の不整合の修正（検査を先に足し、同じタスクで直す）。
- 昇格の判定（`GATES`）・champion の alias・切り戻し。
- 環境の分離、DS 中核の拡張点、統計モデリングのプロファイル。

## やらないこと
- 過去の記録の保存を目的とした後方互換（経緯は git が持つ）。
- 造語を禁じる機械検査。禁止語の一覧は既に作られた語しか知らず、次の新語を必ず見逃す
  （＝自分で不良を作って出口に検査員を置く形になる）。名付けの側は `Registry(require_source=True)` で
  塞ぎ、散文の言い換えは AGENTS の条文＋review スキルの列挙手順で受ける（T-0177・T-0178）。
- 用語表の自動生成。写しを機械で維持するより、写しを置かない（docs は `uv run gates` を指す）。
