# T-0219 符号の契約を挙動で固定する

## 何が問題か（実測 2026-07-11・Python 3.14／sklearn 1.9.0／pyod 3.6.1）
sklearn の `score_samples` は「低いほど異常」（仕込んだ外れ行が argmin）、PyOD の `decision_function` は
「高いほど異常」（同じ外れ行が argmax）。**同じ IsolationForest でも符号が反転する**ことを実測で確認した。
今は `unsupervised.py` の `anomaly_scores`／`AnomalyScore` が符号を反転して「大きいほど異常」に揃えているが、
この性質を守るテストが「住人が増えたら自動で新住人に掛かる」形になっていないと、PyOD の住人を足した
第 1 号で `anomaly_score` の意味が kind ごとに変わる（黙って間違う側の欠陥）。

## やること
- レジストリ駆動の契約テスト：`sorted(ANOMALY)` の**全 kind** に対し、既知の位置に明白な外れ行を
  仕込んだ合成データを採点させ、最大スコアの行が仕込んだ行であることを確かめる。
  対象集合はレジストリの登録から機械的に導く（申告不要＝住人を足した瞬間に自動で対象になる。
  保証の段階は (b) を名乗れる）。
- (B) 経路のエンコーダ（`anomaly_score`）にも同じ向きのテストを置く（(A) と (B) で意味が割れない）。

## やらないこと
- 住人の追加（T-0221）。本タスクは契約の固定だけ。
- 符号の向きを Entry の宣言フィールドで持たせる案（却下。宣言は申告＝L-021 の検出器。挙動のテストが正）。

## 受け入れ基準
- 仕込んだ外れ行の位置（データの構成から既知）が、登録済みの全 kind で argmax になる。
- 対象集合が `sorted(ANOMALY)` から導出されている（テストに kind 名のハードコード列挙が無い。
  別の立場は「符号の逆な住人を仮登録すると、このテストが落ちる」ことで確かめられる）。
- `uv run verify` 全成功。

## 依存の理由
T-0180（`anomaly_score` 列の黙った上書き修正）が同じファイル（`unsupervised.py`）の署名を変えるため、
先に済ませて衝突を避ける。
