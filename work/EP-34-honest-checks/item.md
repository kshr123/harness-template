# EP-34 嘘の検査を本物にする（(b) を名乗る (c) を正す）

## 保証の 3 段階
性質を保証する方法は 3 つある。**(a) 構造的に不可能にする**（型・登録時の `ValueError`・そもそも書けない）、
**(b) 機械が検出する**、**(c) 人が気をつける**。

**(b) を名乗ってよいのは、検査の対象集合が構文・型・登録から機械的に導けるときだけ**（L-021）。
対象集合が「書く人の申告」に依存するなら、それは (b) ではなく (c) である。

このエピックは、**(b) だと信じられていたが実は素通りする検査**を直す。

## 実測で確認した嘘（すべて再現済み）
1. **`verified_by` の `::テスト名` 実在検査は、コメント行で満たせる**。`pm.py:177` が本文への素朴な
   `\b名前\b` 照合なので、`# TODO: test_acceptance を書く予定` だけのファイルで done が通る。
   さらに `::` を書かなければ「実在する無関係なファイル」でも通る。
2. **`coverage_lint` の到達可能性は部分文字列一致**。`serve`（88 回出現）・`status`（19 回）等の 1 語コマンドは
   導線がゼロでも常に合格。「`data blocks` を直接叩かない」という**否定文中の出現**まで導線に数える。
3. **`slow` マーカーは理由不要・全段階で除外・どの CI job でも走らない**＝永久のテスト逃し。
   `skip` は ISS 参照を必須にしているのに、`slow` は素通り。
4. **`item.md` の無いディレクトリ配下の作業単位は、全 PM 検査から消える**。`verified_by` の無い done も素通りする。
5. **core がプロファイルを import しない**という最重要の不変量が、規約 (c) だけで守られている。
   import 文という構文の印があるので (b) にできる。

## 却下した対策（L-017 の適用記録）
- **done 単位の nodeid を full で明示実行する**：done は増え続けるので実行時間が履歴に比例して伸びる。
  同じテストは層別の run で既に走っており、効果は ast 照合と重複する。
- **`slow` を回す CI job を足す**：`slow` マーカー付きのテストは現在 **0 件**。0 件の集合に job を足すと、
  それ自体が exit 5 で空回りする。ISS 必須化（発生源の封鎖）だけでよい。
- **`config.profiles` の逆突き合わせ**：非 DS 複製先は `profiles = []` が**正規手順**なので、
  正規の複製が毎回 allowlist の儀式を踏むことになる。免除が既定になる検査は弱い。
  複製手順の側で「使わないプロファイルを外す」を機械化する（EP-31）方が発生源に近い。
