# EP-47 WBS の並べ替えと拡大縮小

実際に触って出た指摘。

## 分解
- T-0260 … 行の順序を持たせ、右クリックで上・下に足せるようにする（「＋」は撤去・どの行のどの階層かを明示）
- T-0261 … ガントを日・週・月の単位で見られるようにする
- T-0262 … 時間軸を読める形にし、単位の切り替えを実際に効かせる（独立レビューの指摘）
- T-0263 … 見た目を作り直す（罫線の重み・領域の分離・3 色の配色）
- T-0264 … 列を意味のまとまりで括り、どの階層にも子を足せるようにする
- T-0265 … 番号の列と細部を整える（No. 見出し・階層字下げ・非稼働帯の撤去・列オフの取り消し線）

## なぜ順序の置き場が要るか
いまの並びは**ファイル名の順**＝実質 ID 順で、ID は既存の最大＋1 でしか採れない。だから「この行の上に足す」が
表現できない（足したものは必ず最後に来る）。順序は他の何からも導けない**人が決める情報**なので、置き場が要る。
作業単位に `order` を持たせ、並びはこれ→ファイル名の順にする。順序を書いていない案件は今までどおり
ファイル名の順で並ぶ（既定の挙動は変わらない）。
