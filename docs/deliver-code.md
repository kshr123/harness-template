# deliver のコード — どのファイルが何を担い、どう組まれているか

- **読者**：人（deliver を保守・拡張する開発者／レビューするエージェント）
- **種別**：explanation（設計）
- **分かること**：`src/harness/deliver/` の各ファイルの役割と、描画・編集の設計判断
- **ここからやること**：コードを読む前に全体像と設計の芯をつかむ

`docs/deliver.md`（WBS・ガントの使い方と提出の作法）の姉妹。こちらは**中身の設計**を説明する：
`src/harness/deliver/` の各ファイルが何を担うか、描画（`render.py`）と編集面（`wbs edit`）の設計判断が
どこにどう書かれているかを、コードを読む前につかめるようにする。読み手は、deliver プロファイルを
保守・拡張したいエンジニア（と、それを助けるエージェント）。この文書が実装と食い違わないことは
`code_doc_lint`（`uv run verify`）が保証する＝モジュールを足したのにここで触れていないと検査が落ちる。

## 設計の芯

1. **WBS はデータではなくビュー**。日程・階層・状態の正本は `work/` の作業単位の木ひとつ。WBS 側に
   第 2 の台帳を持たない（WBS 番号・営業日数・進捗・親の日程は**書く欄が無い**＝毎回導出する）。
2. **導出は 1 か所**（`wbs.py`）。親の日程は子の最小・最大、進捗は末端の done 数 ÷ 末端の総数、遅れは
   終了予定が本日より前でまだ done でないこと。検査（`wbs_lint.py`）も表示（`render.py`）も同じ導出を読む
   ＝画面には出るが検査は見ていない経路を作らない。
3. **編集は正本を直接書かない**（`session.py`）。入力の作業用の写しを作り、確定した「取り込む」操作の
   1 点でだけ正本へ書く＝別の書き手とぶつからず、途中経過が正本に残らず、まとまりでレビューに渡せる。
4. **書く前後で不変条件を見比べ、増えた指摘だけを拒否理由にする**（fail-closed）。競合検出＋書く前の型検査＋
   書いた後の検査。どれか 1 つでも欠けたら 1 バイトも書かない。検査は**作業単位の検査（`pm.lint`）と WBS の
   検査（`wbs_lint`）の両方**を見比べる＝WBS の検査だけを見ると、参照が切れた `depends_on` のような作業単位側の
   壊れ方を通してしまう。
5. **描画の式・箱は 1 種類だけ**（`render.py`）。日付→横位置の式（`_pct`／`_day_pct`）とガント列のセルの
   padding-box を唯一の出どころにする＝式や箱が 2 つあると必ずずれる（見出しと本体の目盛が食い違う）。
6. **中核とプロファイルの境界**。中核（`src/harness/`）は deliver を知らない。deliver は config
   （`profiles=[..., "harness.deliver"]`）経由でだけ現れる。openpyxl 等はプロファイル経路の外では import しない。

## 全体像（流れとファイルの関係）

正本（`work/` の木＋`docs/wbs.yaml`）を読み、導出して、閲覧・編集・出力の 3 経路に射影する。

```text
  ①入力・導出            ②射影（描画）         ③出力・編集              ④由来・検査
  overlay.py             render.py             cli.py                   stamp.py
  wbs.py         ──▶     calendar.py    ──▶    formats.py / xlsx.py ─▶  wbs_lint.py
  baseline.py            report.py             server.py（編集面）       events.py

  編集面（wbs edit）の部品: session.py（作業用の写し）・editor.py（1 行書き戻し）・
                          adder.py / remover.py（行の追加・削除）・history.py（Ctrl+Z）
```

## どのコードがどんな役割か

**入力・導出**
- `overlay.py` … 案件固有の上書き（`docs/wbs.yaml`）のスキーマと読み込み（未知キーは `extra="forbid"` で拒否）。
- `wbs.py` … 木→WBS の導出の中核（WBS 番号・営業日数・進捗・親の日程・遅れ）。導出規則は冒頭にまとめてある。
- `calendar.py` … 営業日の数え方（両端を含む）・非稼働日（土日・祝日・休業日）の判定。
- `baseline.py` … 合意した時点（git タグ）といまの計画の差（`wbs diff`）・その時点の再出力（`--at`）。

**射影（描画）**
- `render.py` … 閲覧・編集で共通の HTML 描画（`_STYLE`・時間軸・ガント・貼り付く列）。閲覧と編集は同じ描き方。
- `report.py` … 定例・最終報告の 1 枚（マイルストーン状況・遅れ・今後 N 日・要件トレース付録）。
- `stamp.py` … 由来の刻印（コミット・生成日時・内容の指紋）。指紋は表に出ている値そのものから作る。

**出力・検査**
- `cli.py` … `uv run wbs <サブコマンド>` の入口（typer）。拒否条件（`cli._prepare`）はここに集約。
- `formats.py` … 出力形式の登録簿（`write(wbs, path, *, provenance, draft)`＋拡張子）。入れた依存の形式だけ生える。
- `xlsx.py` … 表計算の写し（読み取り専用。openpyxl が入っている案件でだけ有効）。
- `wbs_lint.py` … WBS の不変条件の検査（`uv run verify` が毎回走らせる。検査項目は `docs/deliver.md`）。

**編集面（`wbs edit`）**
- `server.py` … 編集面の HTTP サーバ（`127.0.0.1` 限定・合言葉・ホスト名検査・放置で自終了）。
- `session.py` … 作業用の写し（`.harness/wbs-edit/tree/`）の管理。正本へ書くのは取り込みの 1 点だけ。
- `editor.py` … そのキーの行だけを置き換える書き戻し（コメント・並び・引用符を残す＝差分 1 行）＋安全 3 段。
- `adder.py` … 行・マイルストーンの追加（ID は既存の最大＋1・分解時は親の日程を最初の子へ移す）。
- `remover.py` … 行の削除（手動行は節の項目も一緒に取る・配下を持つ単位はまとめて消さない）。
- `history.py` … 直前の操作を戻す（Ctrl+Z＝操作前の本文を覚えて書き戻す。プロセス内メモリのみ）。
- `events.py` … 出来事（`docs/wbs.yaml` の `events`）の登録・修正（RRULE を画面の操作へ翻訳・裏で組み立て）。

## 描画の設計（`render.py` の `_STYLE`）

**色は 3 色まで（白・黒・青）＋警告の 1 色（赤）。** 濃さは変えてよいので、黒は 5 段・青は 3 段・赤は 2 段で作る。

- **＋1 色を赤にした理由**：赤は「遅れ」だけに使う（読み落とすと実害が出るのは遅れだけ）。**ガントの棒は
  1 色（青）**にして状態で色を分けない＝状態は行の側で示す（棒と行で二重に持たない）。
- 明るい地・暗い地の両方を持ち、本文の文字は対比 4.5 以上、図形は 3 以上。白黒で刷っても状態の強さの順
  （遅れ＞進行中＞…＞完了）が保たれるように、面・文字の濃さ・左バーで表す。
- **罫線は重みを分ける**：弱（行の区切り・日の格子）／中（週の格子）／強（見出しの下端・月の格子・貼り付く列の
  右）／最強の 2px（**左の表とガントの領域の境目**）。すべて同じ太さだと表計算の初期状態に見える。
- **左の表とガントは別の領域**として 3 重に割る：ガント専用の淡い地色（`--canvas`）・最も濃い 2px の縦罫・
  時間の格子。**状態の行色はガントに入れない**＝棒・格子・今日線は常に無地のキャンバスに載る。
- **状態→視覚の強さは「意味の順」に割り当てる**。**彩度のある面（淡赤）はページ最強の資源なので遅れだけに
  使う**。完了は無彩色の淡い面（`--done-row`）で沈め、文字も専用の淡い灰（`--done-ink`）にして退ける
  （灰の連なりが白に変わる境目＝次にやる所）。進行中・確認待ち・保留は左端 3px の縦バー（進行中＝濃青／
  確認待ち＝淡青／保留＝黒）と状態語の強調で「今ここ」を示す。未着手は無印（白）。
- **整列**（デザインの 4 原則）：文字は左・数値と日付は右・まとまり見出しは中央。時間軸は全段そろえ、数字は
  桁をそろえる（tabular-nums）。番号（No.）は字下げしない（作業名の字下げ＋フェーズの面で階層は分かる）。
- 行の縞は入れない（折りたたむと偶奇が崩れる）。画面では行にかざしたときだけ地色を変える。
- **依存の可視化**：行にかざすと先行（`depends_on`）と後続を淡く光らせる（既存の選択色・新色なし・矢印なし）。
  先行は `data-deps`（JSON）で持ち、後続はその逆写像を画面側で 1 回作る（第 2 の台帳を持たない）。
- **列は意味のまとまりで括る**：見出しを 2 段にし、上の段に「作業／予定／実績」を置く。まとまりの先頭に
  強い縦罫。作業表の見出しは地色を一段濃く（`--head`）＝表の頭だとひと目で分かる。
- **見出しの縦の並びは 時間軸 → レーン → 作業表**。レーンを列名とデータ行の間に割り込ませない。レーンは
  データ行より低くする（`--lane-h`＝14px）。帯の全セルは高さ `--lane-h` ちょうど（縦スクロールで貼り付いた
  ときに実寸とずれて重ならないため）。
- **左の作業表はまるごと固定し、時間軸だけ横スクロールする**（標準のガント）。非ガントのセルは
  `position:sticky`、`left` は JS（`freezePanel`）が各行でガント列の手前まで幅を積み上げて入れる。レーン行も
  データ行と同じ列構成（colspan を使わない）にして幅計算を一致させる。
- **ガントのセルの重ね順は「下敷き → 棒 → マイルストーン → 本日の線」**。番号は 0 と 1 しか使わない（固定列
  2・3／見出し 4 以上と衝突させない）。セルの外へはみ出させない（隣のセルに塗り潰されてかえって消える）。
- **引き伸ばす図形に文字と点を置かない**：軸の日付・◆は SVG でなく割合の位置に重ねる要素で描く
  （`preserveAspectRatio="none"` は列幅で潰れる）。線には `vector-effect="non-scaling-stroke"`。
- **日付→横位置の式は 1 組だけ**（`_pct`／`_day_pct`）、**箱も 1 種類だけ**（ガント列のセルの padding-box）。
  見出しの目盛も本体と同じ背景で、SVG は文書のどこにも置かない。検査：文書に `<svg` が現れないこと／
  同じ日付から作った棒・◆・週ラベルの位置が一致すること／見出しと本体の余白が同じであること。
- **罫線は「1 本に見える近さ」まで寄せない**：細かい単位の線が粗い単位の線に近すぎると 1 本に見えるので、
  そのズームでは細かい方を引かない。近さはズームごとの 1 日の幅（`PX_PER_DAY`＝画面の列幅と共用）で決まる。
- **時間軸の表記**：月＝`2026年`/`8月`、週＝`2026年8月`/`8/3w`、日＝3 段（年月/日にち/曜日・土日は薄く）。
  時間軸の目盛の日付は区間の**左**に寄せる（線の右すぐ＝その区間の始まり）が、棒に添えるラベルは区間の
  **真ん中**に置く（どの線の分か読める）。短すぎて文字が切れる区間にはラベルを出さない。目盛は先頭と年が
  変わるところに年を付ける（毎回出すと重なる／出さないと何年か分からない、の間を取る）。目盛は期間の長さで
  間引く（数年の案件で日付が重なるのを防ぐ）。**「自動」という状態は持たない**（自動は初期値の決め方であって
  利用者が選ぶ状態ではない）。
- **描画の下敷きと期間**：左に表・右に大きな 1 枚のガント、という 2 枚組にはせず、1 つの表にしてバーを各行の
  セルの中に描く（改ページで行とバーがずれない・見出しが各ページに再掲される）。各行に**共通の下敷き**
  （時間軸の格子・今日の線）を敷く＝棒だけだと目盛が無く長さが何日か読めない。格子は線種で 3 段（日/週/月）に
  固定し、**どのズームでも「選んだ単位＋1 つ細かい単位」を常に出す**（月表示でも週線が入る）。描画期間はデータの
  期間を**月の境目まで広げる**（1 日始まり・月末終わり）＝日を数字で並べたとき「1 から月末まで」になり、数日
  しかない案件で棒が端から端まで伸びて「ただの帯」になるのも同時に防ぐ。**横軸は暦日・日数の列は営業日**。
- **印刷**：A3 横。時間軸の見出しは各ページに再掲・行の途中で改ページしない・配色は紙の版に固定。
- **上部はタイトル・本日・期間・操作バー・凡例だけ**（提出先や操作の説明文は出さない＝UI 自体で分かる）。
  操作バーは脇役（小さな薄字・押下時だけ淡いチップ）で、3 群（階層／表示／時間軸）を見た目で分ける。

## 編集の設計（`wbs edit`）

**閲覧と編集は同じ画面**（`render.py` の同じ描き方）。違うのは、直せる欄に書き戻し先の目印が付くことと、
保存の口があることだけ。ファイルに書き出した生成物には保存の口が無い（渡した先で編集はできない）。

**画面からの編集は正本を直接書かない**（`session.py`）。`.harness/wbs-edit/tree/` に入力（`work/**` と
`docs/wbs.yaml`）の作業用の写しを作り、サーバはそこだけを読み書きする。正本へ書くのは「取り込む」操作の
1 点だけ。**第 2 の正本ではない**ことは構造で言える：正本の消費者（`status`・`verify`・`task-lint`・
`wbs export`・`wbs diff`）は誰も写しを読まない／`.gitignore` でコミットできない／`session.json` が
「どの正本の状態から写したか」を指紋で持つ（エディタの未保存バッファに当たる）。

**取り込みは 2 段**：まず何がどう変わるかを見せ（行の変化とファイルの生差分の両方）、確定で初めて書く。
書く前に 3 つ全部を確かめ、どれか 1 つでも欠けたら**1 バイトも書かない**：(1) 変える対象の正本が写した時点
から動いていない、(2) 取り込んだ後の姿を先に組み立てて検査し**増えた指摘**が無い、(3) 差分を見せたときと
同じ土台。自動ではコミットしない（コミットは作業単位 ID が要る人・エージェントの行為）。**破棄**すると写しを
取り直す。サーバを閉じても写しはディスクに残るので、開き直せば続きから直せる。Ctrl+Z は写しの中の操作で、
正本を戻すのは取り込み以後＝git の領分。

**書き込み先は正本ひとつ**（`editor.py`）。作業単位の値は `work/` の frontmatter へ、手動行の値は
`docs/wbs.yaml` へ、**そのキーの行だけを置き換えて**書き戻す＝コメント・並び・引用符が残り、差分は 1 か所
あたり 1 行に収まる（差分だけを見る独立レビューが成り立つ）。直せる欄は決め打ちの一覧だけで、導出される値
（WBS 番号・日数・進捗・親の日程）には編集の口が無い（画面から矛盾を入力できない）。

**チーム・担当は名簿から選ぶ**（`docs/wbs.yaml` の `teams`・`members`）。名簿に無い名前を入れるとその名簿にも
足される（選ぶ先と使われている名前がずれない）。

**右クリックは列ごとに変わる**。クリック＝値の編集（唯一の編集面）、右クリック＝一発コマンドと役割を分ける。
- **作業（名前）列**＝構造操作の唯一の置き場（`adder.py`／`remover.py`）：上／下／子に追加・マイルストーンを
  下に追加・削除。改名はクリックでできるのでメニューに出さない。ID は既存の最大＋1（再利用しない）。ファイル
  1 つの軽い単位の下には置けない（親はフォルダで表す）。**未分解の単位を分解すると、その単位の日程・工数は
  最初の子へ移る**（子ができた瞬間に親の日程は導出値になるため）。**足した結果として検査に落ちる場合は、
  足したものを消して理由を返す**。配下を持つ単位はまとめて消さない（何が消えるか画面から見えないため）。
- **状態列**＝一発設定（上位の行は「配下をすべて〈状態〉にする」＝`POST /cascade`。書くのは末端の正本だけで、
  上位の表示は導出で追随する）。末端をまとめて書いたあと検査を**1 度だけ**行い、増えた指摘があれば**全部書き戻して
  断る**（部分適用しない）。1 操作＝1 手なので Ctrl+Z でまとめて戻る。
- **日付列**＝今日にする／クリア。**チーム・担当列**＝クリア。いずれも同じ編集セルへの保存を呼ぶ（競合検出も
  同じ経路）。選択肢は日本語で出し、送るのは正本の値。
- **導出列**（WBS 番号・日数・進捗・ガント）＝無反応にせず「何から導かれるか」を説明する（無反応は故障に
  見える）。作業列以外の末尾には「行の追加・削除は『作業』列で」の道しるべを置く。

**安全のために 3 つ重ねる**（`editor.py`・`server.py`）：
1. **競合検出** … 画面を開いた時点のファイルの指紋を保存時に突き合わせ、違えば書かずに拒否（読み取りから
   書き込みまでを 1 つの錠で囲む・成功時は新しい指紋を返す）。
2. **書く前の型検査** … 新しい本文を組み立てた時点で読み直し、読めなければ書かない。
3. **書いた後の不変条件の検査** … `wbs_lint` に失敗したら元へ戻して理由を画面に出す。

**Ctrl+Z**（`history.py`・`server.py` の `/undo`）：操作が触ったファイルの操作前の本文を覚えて書き戻す
＝逆差分も 1〜数行に収まる。記録はプロセス内メモリだけ（生成ビューに影の状態ファイルを作らない）。戻す前に
指紋を照合し、別の手で正本が動いていたら打ち切る（推測で部分適用しない＝fail-closed）。redo は持たない。

**バーを掴んで動かす編集は作らない**。営業日への吸着と依存の玉突きを素の JS で書くと最も検査できない塊に
なる（セルの編集で「参照でき編集できる」は満たせる）。書き込みの口を守るのは**ブラウザ越しの攻撃**まで
＝同じ計算機に入れる別の利用者は画面を読めば合言葉を取れる（共有の計算機では編集面を立てたままにしない）。

**出来事の登録**（`events.py`）：出来事の帯の空きをクリック／右クリックから、名前・帯・繰り返しを入れて足す。
繰り返しは画面の操作（毎週／隔週／毎月第N／単発＋曜日ボタン）で完結し、**RRULE の文字列は画面に出さない**
（裏で組み立てて送る控え）。合否の門は UI でなく `Event`／`Overlay` の読み込み検査（有限性・開催日 1 件以上・
ID 一意）＝素人が UI を使っても無限の規則や空の出来事は取り込めない。○（開催日）の右クリックで「この回を
開催しない」（exdate）・修正・削除もできる。

**レーンと出来事の設計**（なぜ出来事に `status` 欄が無いか）：

- **レーンは既にあるデータの型から導く**（行にレーンを指定する欄を足さない）。マイルストーンのレーン＝
  `milestone: true` の行を集めた導出、出来事のレーン＝`events` を `lane` ごとにまとめたもの（`lane` の名前は
  案件が自由に決める＝定例／インナー／報告 など）。レーンのクリックの既定はその帯の種類で決まる（マイルストーン
  帯＝その日の節目を `work/` へ登録／出来事の帯＝その帯の出来事を登録）。
- **出来事は「完了状態を持たない、有限個の開催日の集合」**。**期間でなく開催日の集合**として持つのが要点で、
  隔週の定例に長い帯を引くと「ずっとやっている」という嘘になる。1 回きりの会は `rdate` を 1 件書くだけで
  繰り返しと同じ型で表せる。開催日の一覧は導出（保存しない）。描き方は開催日ごとの印で、続いている日（合宿
  など）だけ幅を持つ＝印と期間の区別は描画時の導出。
- **`status` の欄をそもそも持たせない**：完了を持たないものに状態欄を作ると、意味の無い値を毎回埋めることに
  なり、進捗の分母にも入ってしまう。出来事は木に入らないので進捗に数えられず、`depends_on` の先にもなれず、
  レーンと下の表に二重に出ることも起きない。
- **出典**：RFC 5545（iCalendar）が、完了を持つ VTODO と持たない VEVENT を**型として**分けている。この型の
  分離を持ち込むことで、「完了を記録したい」と思った時点でそれは出来事でない、が型で守られる。

## どこに・何が・どう書かれているか（内容の在り処）

案件ごとに変えるのは**宣言**（左）で、**コード**（右）は据え置く。

| 内容 | 宣言（案件ごとに書く） | それを扱うコード |
| --- | --- | --- |
| 階層・日程・状態 | `work/` の frontmatter | `wbs.py`（導出）・`wbs_lint.py`（検査） |
| 暦・節構成・手動行・名簿 | `docs/wbs.yaml` | `overlay.py`（読み込み） |
| 合意した時点 | git のタグ | `baseline.py`（差・再出力） |
| 出せる形式の在庫 | —（依存の有無で機械決定） | `formats.py` → `uv run wbs formats` |
| 由来（コミット・生成日時・指紋） | —（出力時に自動） | `stamp.py` |

## 拡張ポイント

- **出力形式を足す** … `write(wbs, path, *, provenance, draft)` の形の関数と拡張子を `formats.py` に登録する
  だけ（導出は 1 か所なので形式側は書き出すだけ・拡張子も登録簿が持つ）。例は `xlsx.py`。
- **検査を足す** … `wbs_lint.py` に不変条件を足す（表示と同じ導出を読む）。項目一覧は `docs/deliver.md`。
- **暦の規則を変える** … `calendar.py`（営業日・非稼働日の判定）。案件固有の休業日は `docs/wbs.yaml` の宣言で。
