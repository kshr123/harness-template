# REQ-005：WBS は作業単位の木からの生成物であり、日程の第 2 の台帳を作らない

## 内容（何を満たすか）
WBS・ガントは `work/` の作業単位の frontmatter（`start`/`due`/`effort_days`/`milestone`/`status`/`depends_on`）と、
案件固有の薄い上書き（`docs/wbs.yaml`＝カレンダー・顧客向けの節構成・`work/` に置けない手動行）だけを入力に
生成する。階層は `work/` のフォルダ構造から取り、WBS 側に階層を二重に持たない。WBS 番号・営業日数・進捗率・
親のロールアップは**フィールドとして存在しない**（保存できない＝手書きが構造的に不可能）。

## 受け入れ基準（どうなったら満たすか。確かめられる形で書く）
- [ ] `docs/wbs.yaml` のスキーマに、WBS 番号・日数・進捗率・親行の日程を保存する欄が 1 つも無いか（`extra="forbid"` で未知キーも拒否されるか）。
- [ ] `work/` の単位を指す節の項目に、状態・実績日を書く欄が無いか（あれば同じ事実が 2 か所に書ける）。
- [ ] tmp_path 上に組み立てた木の frontmatter を変えて再生成したとき、出力は完全に追随するか（生成物に手で足した情報が生き残る経路が無いか）。
