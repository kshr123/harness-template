# DoD（完了の定義）

タスクが「完了」と言えるのは、次をすべて満たすときだけ。自己申告では完了にしない。

- [ ] `uv run verify` にすべて成功する（作業単位の検査＋完了↔検証の結びつけ＋ruff＋mypy＋pytest）。
- [ ] 受け入れ基準（タスク本文の「受け入れ基準」）を満たす。その基準を確かめるテストを `verified_by` に明記し、それが検証コマンドの成功に含まれている（「全体が通っている」だけでなく、そのタスク固有の基準が検証されている）。
- [ ] 頼まれた範囲の外を変更していない（変更したなら別タスク／変更管理にする）。
- [ ] 独立した確認（作った本人・同じ文脈のエージェントとは別の立場での確認）で、重大な問題が指摘されていない。指摘されている間は完了にしない。
- [ ] 気づき（使いにくかった点を含む）があれば `docs/learnings.md` に記録した。
- [ ] 再利用する部品（`src/` の関数・クラス・レジストリ項目・雛形）を作った・変えた場合：**入口を同じタスクで更新した**——①レジストリに登録しカタログ（`uv run data blocks` / `data encoders` / `data list` / `data models`）に載る ②docstring に「何をするか・config での書き方」がある ③該当スキルか雛形からの導線がある。入口の無い部品は done にしない（`docs/decisions/DEC-0009`）。
- [ ]（チームで進める場合）PR が CI にすべて成功し、独立したレビューの承認を得てマージされた（重大な問題の指摘はマージをブロックする）。

進捗（`STATUS.md`）は生成物なのでコミットしない。見たいときに `uv run status` で作り直す（一致の確認は完了の条件にしない）。
