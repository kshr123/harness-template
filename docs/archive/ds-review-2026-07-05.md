# ds/ コードレビュー（2026-07-05・EP-11 完了時点）

対象＝`src/harness/ds/`（15 ファイル・約 3,500 行）。観点＝プロジェクト全体として最適な構造・構成、各ファイルの
正しさ、モダンで最適なライブラリ選択。EP-08 時点の `docs/structure-review-2026-07.md`（土台全体）に対し、本レビューは
**DS 実装の中身**に踏み込んだ続編。

## 総評
素性は良い。層構造（schema/store/data → features/pipeline → cv/eval/experiment → analysis/eda/unsupervised、
models.py はストア、forecast.py は別背骨）は明快、レジストリの説明文必須はテストで強制、リーク防止は「規約」でなく
**構造**（run_cv の clone-per-fold・OOF mask・valid 重複検出・TargetAggregate の内側 OOF）で担保できている。
polars↔numpy を `_to_numpy` の 1 点に集約する方針も妥当。指摘の大半は「設計が主張しているが実装が追いついていない継ぎ目」に集中。

## 直したこと（genuine な正しさバグ・今やる＝EP-12）
下表は本レビューで確認し、EP-12 で修正した欠陥。★＝原典で確認、◇＝実環境（polars 1.42.1 / sklearn 1.9.0）で実証。

| 場所 | 欠陥 | 影響 |
|------|------|------|
| `eval.passes` ★ | 指標が NaN だと合否が fail-open（`<`/`>` の対が両方 False）| 発散モデルが絶対関門を通過し champion 昇格 |
| `models.promote_model` ★ | 向きが引数任せで METRICS レジストリと矛盾しうる | `log_loss`/`rmse` で悪い方を昇格 |
| `models._versions`/`load_model` ★ | 孤児 version ディレクトリが辞書順で最新化 | 以後 `load_model(version=None)` が恒久エラー |
| `schema.validate` 型検査 ◇★ | `str(dtype)` が `Datetime(...)` で宣言名と一致せず | Datetime/Duration 列が保存不能＝時系列経路を封鎖 |
| `schema.validate` NaN ◇ | NaN は null でないため nullable/range をすり抜け | 破損 float が「検証済み」で保存 |
| `schema.validate` 複合鍵/一意 ◇ | 複合 primary_key 未検査・unique が null 数依存 | 重複キー行の黙認 |
| `cv._predict` ★ | `predict_proba[:,1]` は「classes_ の2番目」＝陽性クラスと限らない | ラベル `{1,2}`/`{-1,1}` で静かに誤った AUC/accuracy |
| `cv.fold_indices` ★ | 重複 id を集合比較と dict 潰しで黙認 | 再現契約が静かに破れる |
| `cv.run_cv` | train/valid の重なり・長さ不一致を未検査 | 明示的なリーク形が素通り |
| `eda.psi` ◇ | ビン端が train min/max＝範囲外の test 値が脱落し正規化で消える | 重度の裾ドリフトで PSI≈0「安定」 |
| `eda.correlations` ◇ | null 1 個で相関 NaN 化、polars ソートで先頭に | 相関ランキング汚染・重複列の検出漏れ |
| `pyproject` ds floor ◇ | `TargetEncoder(cv=obj)`＝sklearn 1.9、polars `nulls_equal`/`empty_as_null`＝1.17 超が必要なのに floor が下 | 下流の最小解決で fit 時クラッシュ |
| `pipeline._to_numpy` | 疎行列を無条件 densify | 大語彙 tfidf で OOM（疎対応モデルは疎のまま通す。疎非対応の HistGradientBoosting だけ工場側 `_dense_model` で密化＝独立レビューで検出した退行を補修） |

各修正はテスト先書き（pre-fix で失敗を確認）→修正→独立レビュー→`uv run verify` 緑で done。詳細は work/EP-12。

## 意図的に先送り（Rule of Three・別途 ISS）
`docs/structure-review-2026-07.md` が「2 つ目のドメインが出るまで保留」と決めた項目に、本レビューは**2 回目の実例**を
足した。3 回目で昇格（機械検査・抽象・スキル・規約のどれか）。今は触らない＝過剰な構造いじりを避ける。

- **「4 作法」の重複**（store.py / models.py / schema.py で URI 解決・tmp→rename・sha256・manifest がコピペ、既に乖離）
  → ISS-0006。structure-review §中⑧の 2 回目。S3 アダプタ着手が抽出のトリガ。
- **実験 config が型無し**（`run_experiment` 12 引数・`threshold`/`thresholds` の混同）→ ISS-0007。
- **レジストリ形のばらつき＋`DATA_SOURCES` に入口なし**（DEC-0009 の隙間）→ ISS-0008。structure-review §低⑩の 2 回目。
- **二値分類のハードコード**（`_predict[:,1]`・`labels=[0,1]`）＝多クラスで静かに誤る → ISS-0009。
- **schema 検証の高度化**（`Column.checks` はパースするが未評価＝誤った安心／cross-column は pandera 導出が向く）→ ISS-0010。
- **DS の効率と忠実性**（`silhouette_score` に sample_size 無し＝O(n²)／`threshold_table` が O(n²)／`TargetEncoder` が分類でも
  非層化 KFold／eda の行ループ）→ ISS-0011。
- **モデル永続化の format 継ぎ目**（pickle 単一・skops 化）は structure-review §低⑫のまま保留（再確認のみ）。
- 将来 extra（umap/optuna/shap・`hashlib.file_digest`）は案件が要求してから。

## 触らない方が良い所（過剰修正の防止）
run_cv の clone-per-fold（リーク防止の核）／手書き CV ループ自体（部分被覆 OOF＝`cross_val_predict` で賄えず正当）／
forecast の分離（DEC-0007）／permutation importance の自作（polars/list 列のため文書化済）／pandas を入れない方針／
`ds/` の平ら構成。いずれも正しい判断なので維持。
