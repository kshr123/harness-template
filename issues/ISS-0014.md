# ISS-0014 coverage_lint が [project.scripts] の plain main（typer.run 型）を導線検査の対象にしない死角

## 事象
coverage_lint（EP-19）の AST 走査は typer の `@<app>.command("name")` 装飾子だけを拾う。
`[project.scripts]` に登録した plain main（`typer.run(...)` を呼ぶ関数。例 verify/status/changelog、
T-0101 の `commit-msg-lint`）は装飾子を持たないため**導線検査の対象外**になり、スキル/正本 docs から
未到達でも verify が緑になる（＝DEC-0016「新 CLI は導線必須」の機械検査に穴）。

## 根拠・影響
- T-0101 の独立レビューで実測：`commit-msg-lint`（plain main）は coverage_lint に不可視。緑なのは
  AGENTS.md 導線のおかげではなく「見えていないから」。既存の verify/status 等も同型の既存ギャップ。
- 影響：エージェントが `[project.scripts]` 経由でコマンドを足すと、導線を張り忘れても検査が素通りする。
  現状は運用（レビュー観点）で補われているが、機械化の趣旨からは死角。
- 対処案（別タスク）：coverage_lint を `[project.scripts]` の entry も走査対象にし、各コマンドが
  スキル/正本 docs から到達可能かを検査する（typer command と同じ到達性判定に載せる）。偽陽性
  （内部専用コマンド）には理由必須 allowlist（`_EXEMPT` 同型）。EP-20 T-0103 or 後続で検討。
