# ISS-0018 ヘッドレス実測テストの Chrome 依存

## 事象
T-0288 で、依存ホバーの受け入れ基準（かざすと先行/後続の行に `dep-hi` が付く）を、実ブラウザで
`mouseenter` を発火させて DOM を確かめるヘッドレス実測テストにした（文字列パースでは変異が緑のまま通る、
という独立レビュー D3 の指摘への対処）。テストは Chrome の実体（macOS の既定パス・`google-chrome`・
`chromium`）を探し、**見つからなければ本 ISS を参照して skip する**。

## 影響
Chrome を入れていない CI・開発環境では、この実測テストが skip される（＝その環境では「回っていないのに緑」）。
開発機（Chrome あり）では実行され、逆写像・`mark` の変異を RED で捕まえる。fail-open ではない（データ側の
`data-deps` 検査と JS 構文検査は Chrome 無しでも常に回る）が、runtime 挙動の担保は Chrome のある環境に限られる。

## 対処の方針（決めてから着手）
CI のジョブに headless Chrome を入れ、この実測テストを skip させずに必ず回す（案件テンプレートの CI 雛形へ
Chrome セットアップの 1 段を足す）。ブラウザ実行テストの土台（`tests/_headless.py` のロケータ＋dump-dom 実行）は
再利用できるので、他の UI 受け入れ基準にも広げる。
