# ISS-0016 来歴ヘルパ（_git_provenance/_dependencies/_lock_fingerprint/_utcnow）が ds/models.py と agent/store.py に複製されている

## 事象
昇格の保存機構は `harness.promotion`（中核）へ 1 本化したが、来歴を集める補助関数
`_git_provenance`（git の commit/branch/dirty）・`_dependencies`（配布物の版）・`_lock_fingerprint`
（uv.lock の sha256）・`_utcnow`（テストが monkeypatch で固定する時刻の入口）は、いまも
`src/harness/ds/models.py` と `src/harness/agent/store.py` にほぼ逐語で複製されている。

## 根拠・影響
これらは「保存物に付ける由来書き」を作る仕組みで、昇格機構と同じく本来は中核に置ける
（`storage.py` 相当の policy-free な部品）。複製が残るぶん、片方だけ直す退行（例：encoding の明示や
dirty の定義を一方でだけ直す）が起きうる。ただし promotion への抽出とは関心が別（保存の by-product で
あって昇格の判定ではない）なので、同じコミットに混ぜず別タスクに切り出す。

## 対処の方針（決めてから）
`harness.provenance`（または `storage.py` へ追補）に `git_provenance`/`dependencies`/`lock_fingerprint`/
`utcnow` を抽出し、ds/models.py・agent/store.py を薄い呼び手にする。`_utcnow` はテストの monkeypatch 点
なので、抽出後もプロファイル側から差し替え可能な形（呼び手が時刻を渡す／プロファイル側に薄い委譲を残す）を
選ぶこと。着手はどちらかのプロファイルで来歴の仕様を触るときに合わせる。
