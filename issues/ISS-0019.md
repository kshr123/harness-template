# ISS-0019 Windows パス区切りの残存箇所・doclint 免除の広さ

EP-50 の独立レビュー（2026-07-30・PASS）が挙げた非ブロックの follow-up。今回の CI は全緑だが、将来
Windows で顕在化しうる同種の穴と、免除の広がりを記録して落とさないようにする。

## 事象
1. **`\` 区切りに依存する残存箇所**（EP-50 で直したのは code_doc_lint のメッセージ 1 か所のみ）：
   - `src/harness/pm.py:468` 付近、`src/harness/agent/lint.py:30` 付近＝メッセージ出力で `relative_to` の
     生 str を使う（Windows で `\`）。今はテストが当たっていないので緑。
   - `src/harness/deliver/session.py:50` の `inputs_of` が `str(p.relative_to(root))` を**編集セッションの
     指紋キー**に使う。同一プラットフォーム内では書きも読みも同じキーなので機能は壊れないが、Windows では
     キーが `\` 区切りになる（正本＝WBS の deliver プロファイル。将来クロス環境で照合すると食い違う）。
   対処案：リポ相対パスを文字列化する箇所は一律 `as_posix()`（プラットフォーム非依存の 1 か所ヘルパにしてもよい）。
2. **doclint の案件領域免除がやや広い**（`_is_case_area`）：
   - `fnmatch` は `*` が `/` を跨ぐため、`docs/structure-review-*.md` が `docs/structure-review-x/y.md` の
     ような入れ子も免除する（pathlib の glob より広い）。今日は無害。
   - ID 形でない案件領域パス（例 `work/README.md`）は doclint（免除）と doc_source_lint（正規表現が
     `work/(EP|T|E|INV)-…` のみ）の両方をすり抜ける。意図した禁止は ID 形で覆えているので実害は小さい。
   対処案：免除判定をディレクトリ境界で行う（`fnmatch` でなくセグメント一致）／必要なら doc_source_lint の
   対象を広げる。

## 影響
現状 CI 全緑・実害なし。Windows 常用や、案件領域の非 ID パス参照が増えたときに顕在化しうる。

## 対処の方針（決めてから着手）
1 は「リポ相対パスの文字列化は必ず `as_posix()`」という小さな規約＋一括修正で潰せる（機械検査に落とせるかは要検討）。
2 は免除の意味論（ディレクトリ配下か・glob か）を決めてから。いずれも EP-50 の範囲外として切り出す。
