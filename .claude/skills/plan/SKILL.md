# plan（どう作るかを決める）

## 手順
1. SPEC（何を作るか）を読む。テンプレート `.harness/templates/plan.md` を使い、その単位のフォルダ `work/…/PLAN.md` にまとめる。
2. 「作り方の大枠」「影響するファイル・インターフェース」「決めたことと理由」「やらない範囲」を書く。
3. **分解は全体→詳細**：最初のタスクを「端まで通る最小の骨組み」（入力→処理→出力→検証が一巡・verify 全成功）にし、以降を骨組みの差し替えとして並べる（既定の進め方・`docs/method.md` A 節）。
4. 実装の前に人のレビューを受ける（承認されてから実装に進む）。まだ決まっていない点は `[要確認]` で残す。

## してはいけないこと
- 実装に飛びつかない（先に作り方を決めて合意する）。
- 頼まれていない機能を足さない。起きない場合への備えを作り込まない。
