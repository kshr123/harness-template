# wbs（顧客向けの WBS・ガント＝作業単位の木の生成ビュー）

**WBS はデータではなくビュー。日程の正本は `work/` の作業単位ひとつ。** 契約・用語・スキーマの正本は
docs/deliver.md。ここは場面ごとの手順。

日程を直すときは `work/` の frontmatter（`start`・`due`・`effort_days`・`milestone`）を直す。WBS 用の
ファイルに日程を書く欄は無い（書けない）。`docs/wbs.yaml` に書くのは、暦・顧客向けの節の構成・
`work/` に置けない行（クライアントの承認待ち・定例会議・先方の作業）だけ。

## はじめに一度だけ
1. `uv sync --extra deliver`（表計算も出すなら `--extra openpyxl`）。
2. `.harness/templates/wbs.yaml` を `docs/wbs.yaml` にコピーして、案件名・提出先・暦（休業日）を書く。
   節の構成は、顧客の言葉と `work/` の構造がずれるときだけ書く（書かなければ木をそのまま使う）。
3. 合意する計画ができたら **git のタグを打つ**（例 `git tag 要件定義-合意`）。これが後で差を説明する基準になる。

## 場面ごとの手順

### 提案・キックオフ（計画を合意する）
1. フェーズを `work/` のエピックとして作り、まだ分解しないものは日程だけ置く（子がいない単位は自分の
   日程を持てる＝粗い粒度で描ける）。分解したら親から日程を外す（親は子から導くので、残すと検査が失敗する）。
2. クライアント側の作業・承認待ち・定例は `docs/wbs.yaml` の `rows:` に手動行として置き、`sections:` の
   並びに混ぜる。
3. `uv run wbs export` → できた HTML をブラウザで開き、印刷から PDF にして渡す。
4. 合意したら `git tag <名前>`。

### 定例会議（進捗を報告する）
1. 直前に `uv run wbs export`（未コミットがあると拒否される。すぐ出したいときだけ `--draft`）。
2. 遅れている行（予定終了を過ぎて未完）に印が付いているので、そこだけ話す。
3. 前回からの差を聞かれたら `uv run wbs diff <前回のタグ>`。

### 計画を引き直す（遅延・スコープ変更）
1. `uv run wbs edit` を起動し、ブラウザでセルを直す（保存すると正本の該当行だけが書き換わる）。
   まとめて動かすときはテキストで直すか、エージェントに頼む方が速い。
2. コミットのメッセージに**理由を書く**。`uv run wbs diff` がこのメッセージをそのまま理由として出すので、
   別の場所に書き写す必要はない。
3. 再合意したら新しいタグを打つ。

### 最終報告
1. `uv run wbs export` … 予定（`start`/`due`）と実績（`created`/`closed` から導出）が並んで出る。
2. `uv run wbs diff <最初の合意のタグ>` … 当初計画からの全ての動きと、その理由（コミット）。
3. `uv run wbs export --at <最初の合意のタグ>` … 当初計画そのものを出し直して並べる。

## 困ったとき
- 出力が拒否される → 理由が出る。検査の失敗（`uv run wbs lint`）、日程を持つ単位が 0 件、未コミットの変更、
  のいずれか。**空の工程表・嘘の由来を渡さないための拒否**なので、黙らせずに直す。
- 「親が自分で日程を宣言している」と言われる → その親は子を持っている。子に日程を置き、親からは外す。
- 「どの節にも載っていない」と言われる → 顧客向けに出さない単位は `docs/wbs.yaml` の `exclude:` に書く
  （黙って消さない）。
- 表計算で欲しいと言われた → `uv sync --extra openpyxl` して `uv run wbs export --format xlsx`
  （出せる形式は `uv run wbs formats`）。

## してはいけないこと
- WBS 用のファイルに日程・状態・階層を持たせない（`work/` と二重になる。そもそも書く欄が無い）。
- クライアントが編集した表計算を取り込む口を作らない。変更の要望は `docs/demands/` に要求として起こす。
- 生成物（`artifacts/`）をコミットしない。渡した版を残したいときは、生成物でなく git のタグで固定する。
- 進捗率を手で書かない（末端の done 数から導出される）。
