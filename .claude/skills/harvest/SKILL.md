# harvest（振り返って次に活かす）

気づきを durable な資産へ昇格させ、後戻りさせない（進化の歯止め）。全体像は `docs/method.md` C 節。

## 手順
1. 気づき（工夫・使いにくかった点）を `docs/learnings.md` に記録する（1 件＝1 項目・なぜも・状態: 記録のみ）。
2. 既存の learnings を見て、**2 回目が出た項目**があれば決定（`docs/decisions/DEC-xxxx`）を起こし、落とし先を 1 つ選ぶ（判定表は method.md C 節：機械検査／抽象／スキル／規約）。
3. 昇格するルールは、**先に「違反すると失敗する検査」を足してから**直す（テスト先行と同じ・退行を機械で止める）。検査にできないものは AGENTS に 1 行＋「（レビュー観点）」の印。
4. 昇格したら learnings を「状態: 昇格済み → DEC-xxxx」に更新し、次の見直しで消す（正本が移ったので）。使われていないスキルの統廃合を検討する。逆に、**入口の無い部品**（カタログに載らない・どのスキルからも導かれない `src/` の再利用部品）が無いかも見る（あれば入口の追加を 1 タスク起こす・DEC-0009）。あわせて**スキル・規約の記述が決定（DEC）と矛盾していないか**を 1 点見る（決定で撤去した仕組みを古いスキルがまだ指していないか。正本は DEC 側・スキルは追随する）。
5. 2 つ以上の案件で役立ったものだけを、共通の開発基盤（テンプレート側）へ取り込む（1 回だけのものは案件側に置く）。

## してはいけないこと
- リポジトリや履歴が既に記録することは書かない。1 回きりの工夫を基盤に入れない。
- 正本を 2 か所に書かない（他の層はリンクで参照）。古くなった記録は消す（ためこまない）。
